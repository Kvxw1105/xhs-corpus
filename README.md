# xhs-corpus · 小红书语料采集工作流

把「刷小红书」变成可复现、可续跑、可沉淀的知识生产流水线。

> 一个经过实战验证的采集方法论：搜索池 → 正文采集 → 图卡转录 → 评论层 → 结构化语料库 → 知识库沉淀。
> 首个完整验证案例：考研英语方法大搜索（57 关键词 → 701 帖池 → 211 帖全文）+ 博主专项（223 篇主页、27 页图卡 100% 转录）。

## 这是什么

一套**只在页面前台可见层工作**的小红书语料采集方法，不调接口、不注入抓取、不模拟协议——因为它依赖的不是一个爬虫，而是：

1. 一个可编程的真实浏览器通道（内置浏览器 / CDP 真实输入事件）
2. 一套与平台共存的**拟人节奏纪律**
3. 一条**断点续采**的状态管理链（所有状态落盘 JSONL，任何中断零损失）
4. 图卡帖的**轮播翻页 + 逐字转录**流水线

## 核心设计

```
关键词矩阵（广撒：同义词/黑话/分数档/情绪词）
   ↓ 每词搜索 → 页内直采卡片（id + xsec_token + 标题）
搜索池 JSONL（断点续采，去重累积）
   ↓ 分桶限额筛选（邪修/技巧/方法论/经验贴…）
正文采集（逐帖 goto → 抓 title/author/desc/评论数 → 追加落盘）
   ↓
图卡帖分支（轮播翻页 → 截图 → 多模态逐字转录 → 与官方AI转录互校）
评论层（主楼+回复展开，网页端有 10 主楼平台上限，如实记录）
   ↓ Python 聚合
成品 Markdown（分桶/分类/原始件引用）→ 知识库（Obsidian 三层结构）
```

## 为什么不是爬虫

- **零对抗**：平台看到的就是一个正常登录用户在正常浏览。没有接口逆向、没有签名破解、没有频控对抗。
- **可解释**：每条语料都对应一次真实的页面浏览，可回放、可截图、可审计。
- **有边界**：平台不给的（评论区全量分页、视频内容）就拿不到——如实记录"可达上限"，不伪装。

代价也如实说：速度是人工级的（每帖 8-10 秒），规模是百帖级的。要万帖规模请用别的方案，并自己承担后果。

## 平台技巧（实战踩坑换来的）

- locator.click 超时、合成事件被无视 → **IIFE evaluate 取坐标 + 真实坐标点击**
- evaluate 传参必须是 IIFE，函数字面量不会被调用
- 页面滚动挂 `documentElement.scrollTop`，不在 window 上
- 双层视图（弹窗查看器盖住笔记页）时，ARIA 指示器会读到被盖层的旧值 → 真实状态用查看器自己的控件文本
- 点击前 `elementFromPoint` 验证落点；点完验证状态变了没有
- 大图查看器键盘方向键最稳；翻页动画 1s+，截图要等
- 评论展开按钮单步点击 + 逐步验证，绝不批量连点

完整清单见 [skill/SKILL.md](skill/SKILL.md) 第 4-6 节。

## 风控纪律

- 逐次操作间隔 2.5-3.5s 随机停顿，长任务每小时自动歇
- 只读：不点赞、不关注、不评论、不发内容
- 出现验证码/风控页 → 立即 STOPPED_SAFE，写检查点，等下个时段
- 登录用小号；登录态落盘持久，失效重扫即可
- 平台限制（评论分页上限、视频内容）如实记录，不绕过
