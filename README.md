# xhs-corpus

**把刷小红书，变成一条可复现的知识生产线。**

A human-paced, front-end-visible workflow that turns Xiaohongshu browsing
into a reproducible, resumable knowledge pipeline — shipped as an Agent Skill.

*Agent Skill · MIT · 无需逆向 · 无需接口*

</div>

---

## 这是什么

一套经过实战验证的小红书**语料采集方法论**，以 Agent Skill 形态交付。

它解决的问题：手动刷帖收集资料太慢，而爬虫又太难太险。xhs-corpus 走中间路线——
**驱动一个已登录的真实浏览器，只读页面前台可见层，按拟人节奏逐页浏览**，
把整个过程变成可复现、可断点续跑、可审计的知识生产线。

> 首个完整验证：一次考研英语方法大搜索 —— 57 组关键词 → 701 帖搜索池 →
> 211 帖全文采集 + 一篇 27 页图卡帖 100% 逐字转录（约 1.5 万字）+ 粉丝二创生态，
> 全程拟人节奏，零验证码，账号无恙。见 [cases/](cases/)。

## 为什么不是爬虫

| | 典型爬虫 | xhs-corpus |
|---|---|---|
| 工作层 | 接口逆向 / 签名破解 / 协议模拟 | 页面前台可见层（一个正常登录用户看到的） |
| 平台视角 | 异常流量 | 正常用户浏览 |
| 对抗性 | 高（签名一变就崩） | 无对抗（平台改版只需微调选择器） |
| 边界 | 伪装成"什么都能拿" | 平台不给的就拿不到，如实记录 |

代价也如实说：速度是**人工级**的（每帖 8-10 秒），规模是**百帖级**的。
要万帖规模，这个方法不适合你。

## 核心设计

```
关键词矩阵（广撒：同义词/黑话/分数档/情绪词/品牌词）
   ↓ 每词搜索 → 页内直采卡片（id + xsec_token + 标题）
搜索池 JSONL（断点续采，去重累积，任何中断零损失）
   ↓ 分桶限额筛选（按主题切优先级）
正文采集（逐帖 → title / author / 正文 / 评论数 → 追加落盘）
   ↓
图卡帖分支（轮播翻页 → 截图 → 多模态逐字转录 → 与官方AI转录互校）
评论层（主楼 + 回复展开；网页端有平台上限，如实记录）
   ↓ Python 聚合
成品 Markdown（分桶分类 / 原始件引用）→ 知识库（Obsidian 三层结构）
```

## 安装

把 [`skill/`](skill/) 拷进你的 Agent skill 目录（如 `~/.agents/skills/xhs-corpus/`）。
前置条件：一个可编程的真实浏览器通道（内置浏览器 / CDP 注入均可）+ 已登录的小红书会话。

适用于 Claude Code、Codex、ZCode 或任何支持 skill/MCP + 浏览器操作的 Agent。

## 平台技巧精选（完整版见 SKILL.md 第 4-6 节）

- locator.click 会超时、合成事件被无视 → **IIFE evaluate 取坐标 + 真实坐标点击**
- evaluate 传参必须是 IIFE，函数字面量不会被调用
- 双层视图（大图查看器盖住笔记页）时，ARIA 指示器读到的是被盖层的旧值 →
  真实页码用查看器自有控件文本
- 点击前 `elementFromPoint` 验证落点；点完验证状态确实变了
- 大图查看器键盘方向键最稳；翻页动画 1s+，截图要等，否则出残影帧

## 风控纪律（红线）

- 逐次操作间隔 2.5-3.5s 随机停顿，长任务每小时自动歇
- **只读**：不点赞、不关注、不评论、不发内容、不私信
- 出现验证码/风控页 → 立即 STOPPED_SAFE，写检查点
- 用小号；遵守平台条款是使用者自己的责任

## 平台限制（如实记录，不绕过）

- 评论区网页端封顶约 10 主楼 + 回复展开，无分页——标称总数不可达
- 视频帖方法在视频内不可文本提取——用评论区（作者答疑+用户共创）替代
- token 有时效；博主可能删早期帖——粉丝二创生态是第二来源
